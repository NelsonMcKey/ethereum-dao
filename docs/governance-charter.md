# Governance Charter

## Purpose
Define how ETH holders govern the DAO to curate and deploy immutable, ownerless DeFi primitives with minimal or zero fees and ETH-burn economics.

## Governance Scope
- Approve and prioritize DeFi primitives.
- Approve deployments and registry updates.
- Update governance parameters through onchain proposals.

## Eligibility and Voting Power
- Eligibility: any ETH holder can participate.
- Voting power: proportional to ETH balance at a defined snapshot.
- Delegation: optional, non-custodial delegation supported.

## Proposal Lifecycle
- Draft: public discussion period with clear proposal templates.
- Submission: onchain proposal with specification and code references.
- Voting: fixed window with quorum and threshold requirements.
- Timelock: execution delay to allow review and exit.
- Execution: onchain actions only; no admin overrides.

## Proposal Types
- Primitive selection and prioritization.
- Deployment approval for immutable contracts.
- Registry updates (add/remove deployments).
- Treasury allocations and grants.
- Governance parameter changes.

## Quorum and Thresholds
- Quorum: minimum ETH voting participation.
- Approval threshold: minimum yes-vote percentage.
- Parameter tuning: adjustable via governance with timelock.

## Safety and Anti-Capture Measures
- Timelocks on all execution.
- Transparent and immutable proposal data.
- No emergency admin keys.
- Optional proposal sponsorship to reduce spam.

## Treasury Policy
- No treasury or custodial funds.
- No distributions to holders; any protocol fees are burned.

## Registry Governance
- Registry entries must be immutable, ownerless deployments.
- Minimum lindy criteria required for eligible codebases.
- Removal only for provable breaks or security emergencies via governance.

## Open Questions
- Snapshot vs continuous balance voting.
- Minimum quorum and thresholds for early vs mature phases.
- Definition of lindy criteria and exceptions policy.
